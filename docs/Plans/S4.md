# Sprint 4 Plan — SimQC

**Sprint goal:** Introduce cross-validation against established, pre-existing libraries as a standard part of our testing process.

In addition to our existing unit tests and internal correctness checks, every implementation should be tested against an independent, trusted implementation whenever a suitable reference exists. Examples:

- **Cryptographic functions:** Compare our pure-JS SHA-256 (`src/ai/Cache.js`) against Node.js's built-in `crypto.createHash('sha256')`.
- **Complex arithmetic:** Compare `src/core/Complex.js` operations against known analytical values and Python's `cmath`.
- **Matrix algebra:** Compare `src/core/Matrix.js` (multiply, tensorProduct/Kronecker, conjugateTranspose, isUnitary) against NumPy.
- **Quantum gates:** Compare our gate flat-tuples and Matrix forms (`src/gates/basis.js`, `src/gates/param.js`) against Qiskit gate matrices.
- **Hot-path kernels:** Compare `src/sim/kernel.js` (apply1QubitOp, applyCnot, applyCz, applyToffoli, applySwap) against Qiskit/Cirq state-vector simulation.
- **State vector:** Compare `src/core/StateVector.js` (initialization, probabilities, norm, renormalize) against Qiskit `Statevector`.
- **Measurement:** Compare `src/measurement/measurement.js` (Born-rule collapse, shot histogram) against Qiskit measurement counts.
- **Purity & Bloch:** Compare `src/inspector/Purity.js` (single-qubit gamma, linear entropy) and `src/inspector/Bloch.js` (Bloch vector) against Qiskit partial trace + density-matrix computations.
- **Algorithms:** Compare `src/algorithms/qft.js`, `shor.js`, `dj.js`, `grover.js` circuit outputs against Qiskit's QFT, Shor (order finding), Deutsch–Jozsa, and Grover.
- **Serializer / Flatten:** Compare `src/circuit/Serializer.js` v1 JSON round-trip and `src/circuit/Flatten.js` virtual-column scheduling against structural expectations.
- **Sparse summary:** Compare `src/ai/SparseSummary.js` marginals (rho00, S_L) against Qiskit partial-trace probabilities.

The objective is to ensure that our implementations are not merely passing our own tests, but also producing results consistent with established, independently developed implementations.

**Acceptance criteria:** `node --test` passes 100%; every new cross-validation harness has a 1:1 test; SHA-256 output matches Node.js `crypto` byte-for-byte across random inputs; Qiskit differential pipe produces matching state vectors/probabilities for all gate types, Bell, GHZ, QFT, DJ, Grover, and Shor order-finding up to n=6 within `1e-12` (n≤8) / `1e-9` (n>8); matrix ops match NumPy within `1e-12`; purity/Bloch match Qiskit partial trace within `1e-9`; no layering violations; `git status`/`git diff` show only intended files changed.
