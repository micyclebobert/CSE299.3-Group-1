## DONE

### Architecture and code organization

- `StepTrace` was split into the `StepTrace` class plus `step-trace-apply.js` and `step-trace-compare.js`; the class is now 341 lines and both split kernels have exact mirrored tests.
- `Debugger` was split into `Debugger.js`, `debugger-playback.js`, and `debugger-breakpoints.js`; the class is now 236 lines and both split modules have exact mirrored tests.
- `AppController` was reduced from 428 to 231 lines and split into placement, gate-editing, circuit-structure, debugger, inspector, and shots method modules. The split reduced file size, although the resulting filename/export and exact-mirror gaps remain under TODO.
- `src/algorithms/dj.js` and `src/core/SparseSummary.js` now have exact mirrored tests. The AI registry has an exact mirrored test.
- `src/ai/registry.js` is no longer a static re-export barrel: it is a lazy `registry` facade with a primary `registry` export matching its filename and no concrete-module re-exports.
- Browser view filenames were changed from kebab-case to camelCase (`aiBuilderView.js`, `aiExplainerView.js`, `browserApp.js`, `canvasRenderer.js`, `codeView.js`, `debuggerView.js`, `inspectorBlochView.js`, `inspectorHistogramView.js`, `inspectorStateView.js`, `inspectorTabsView.js`, `ioAnalyzerView.js`, `panelView.js`, and `placementView.js`). Primary-export alignment is not yet complete and remains under TODO.

### Core editor, Inspector, and Debugger behavior

- Browser pointer snapping uses the renderer’s 80px column pitch and 48px row pitch with gate-center origin `(80,20)`. Center and inter-cell-boundary regression cases cover the mapping.
- Pointer placement consumes `Interaction.drop()`, reserves the selected target row before allocating controls/`target2`, rejects insufficient-row arity, and creates explicit empty gap columns when needed.
- `AppController.placeGateAt()` and `placeGateFromCell()` reject non-finite, fractional, negative, and out-of-range coordinates without mutating the circuit. Direct placement and browser-drop insertion agree on gap-column behavior.
- Controller/model support exists for selecting, moving, deleting, and replacing gates; keyboard arrow selection and Delete/Backspace deletion; positive/anti-controls; control count; SWAP `target2`; Toffoli controls; parameter angles; qubit-row and column changes; and previous-step/play/pause/run-to-previous-breakpoint transport. Browser controls for most of these workflows are still required under TODO.
- The Inspector renders amplitude and probability tables, phase, full state-vector text, a state-vector probability chart, a register overview, per-qubit Bloch subtabs, and a repeated-shot histogram. The histogram uses true integer sample counts, includes zero-count outcomes, and applies DPR scaling.
- `Debugger` and `DebuggerUI` are created together with each circuit replacement. The controller exposes Step, Run, Reset, scrub/seek, breakpoint toggle/clear, and run-to-breakpoint behavior; valid breakpoints survive edits when still within the new schedule.
- A visible breakpoint contract states that step 0 is the initial state, step `k` is the state after column `k-1`, and a breakpoint at step `k` halts before column `k` is applied. The same explanation appears in the Debugger view and `index.html`.

### Code, URL, AI, limits, and persistence

- The browser shell includes canonical JSON editing/Enter-to-apply, live JSON syntax feedback, JSON download, copy confirmation, a visible read-only compressed share-URL field and copy action with clipboard feedback, non-blocking import/error feedback, JSON file-picker import with feedback, exported-code output, initial `#circuit=` loading, `hashchange` reloads, and dedicated Canonical JSON / Compressed URL / Exported Code / AI Explainer / AI Builder / I/O Analyzer tabs.
- Circuit data can be saved to, loaded from, and cleared from browser local storage with visible success/error status. `PanelModel.applyLayoutRects()` is applied to the CSS grid tracks so collapsed/hidden panels reclaim space; layout persistence APIs exist in `PanelModel`, but browser layout persistence remains under TODO.
- AI Builder has prompt and qubit inputs, error status, deterministic fallback behavior, model-aware cache-key support in its UI model, and an internal retry path. The browser model input, retry/confirmation UX, and visible cache hit/miss state remain under TODO.
- AI Explainer has a browser final/virtual-step selector, visible context describing the boundary and per-column top-k summaries, a deterministic no-LLM fallback, and trace-position restoration through copied state facades.
- I/O Analyzer has model-level final/step boundaries, selected-step validation, sparse top-k state grounding, causal-chain output, and a boundary-sensitive cache key. The browser multi-row selector and bounds feedback are implemented; browser boundary-state wiring remains under TODO. `IOAnalyzer.enrichWithLLM()` now passes the actual instructions, summaries, and qubit count to the explainer instead of explaining an empty circuit, and AI fallback descriptions use the registered gate IDs.
- Controller circuit-ingress paths enforce a hard maximum of 20 qubits and show the 15–20 qubit advisory through visible status. JSON import and AI Builder application refuse over-limit circuits without replacing the current circuit; real-browser verification of every ingress path remains under TODO.
- The Node CLI independently rejects input above 24 qubits before state allocation, exits non-zero, writes the diagnostic to stderr, and emits no stdout.
- AI Builder and I/O Analyzer receive the controller’s injected shared `Cache` instance. Their clear operations preserve instance identity; feature-scoped invalidation and visible hit/miss behavior remain under TODO.
- Browser-facing AI and I/O views use public controller accessors rather than `app._stepTrace`, `app._currentCircuit`, or `app._status()`. `currentCircuit` is immutable, `getStepTrace()` exposes a read-only facade, and `getStateAtStep()` returns copied read-only state.

### Test and documentation assets

- The real-browser CDP path under `test/browser/` can launch Chromium and connect through the Chrome DevTools Protocol; it is not a fake-DOM suite. It still requires a provisioned browser runtime and does not yet cover the required end-to-end workflows.
- Focused scripts exist for UI, interface, features, AI, debugger, simulator, circuit, editor, canvas, measurement, state, algorithms, validation, and cross-validation areas, all routed through `npm test`/`scripts/run-tests.js`.
- The browser integration and model-level suites contain substantial DOM-shim/controller coverage for startup, placement, Inspector tabs, Debugger transport, canonical JSON/URL, AI workflows, I/O analysis, limits, cache identity, and public facades. DOM-shim coverage is retained as supplemental evidence, not browser acceptance.
