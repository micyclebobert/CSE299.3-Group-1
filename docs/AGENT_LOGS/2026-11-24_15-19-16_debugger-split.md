Title: Split src/debugger/Debugger.js into playback and breakpoint modules

Summary:
Split the 484-line src/debugger/Debugger.js (exceeds 400-line cap) into three modules:

- src/debugger/Debugger.js (rewritten, 236 lines): kept constructor, state queries (getCurrentStep/getTotalSteps/getMode/getNumQubits/isAtStart/isAtEnd), state readers (getCurrentState/peekState/getTimelineSummary), callbacks (onStep/onBreakpointHit/onReset/onSeek/onNext), getTimeline(), and static fromCircuit(). The four private fields (#stepTrace, #breakpointManager, #timeline, #callbacks) were converted to regular instance fields because JS private fields cannot be accessed from methods assigned to the prototype from an external module (a hard parse-time error). main.js imports the two extension modules as side-effect imports so Object.assign runs on Debugger.prototype; Debugger.js itself imports neither extension module to avoid an ES-module circular-import/TDZ crash.
- src/debugger/debugger-playback.js (new, 142 lines): Object.assign(Debugger.prototype, { reset, next, seek, runToBreakpoint, runToPreviousBreakpoint, scrub, scrubToStart, scrubToEnd }).
- src/debugger/debugger-breakpoints.js (new, 140 lines): Object.assign(Debugger.prototype, { getBreakpointManager, add/remove/toggle/has/getColumnBreakpoint(s), add/remove/has/toggle/getPredicateBreakpoint(s), findStepWhere, setBreakpointsEnabled, areBreakpointsEnabled, clearAllBreakpoints }).
- src/main.js (+6 lines): imports ./debugger/debugger-playback.js and ./debugger/debugger-breakpoints.js so the mixins load alongside Debugger.
- test/debugger/debugger-playback.test.js (new, 175 lines) and test/debugger/debugger-breakpoints.test.js (new, 130 lines): mirrored 1:1 tests.

Verification:
- node --check passes on all six touched files.
- All 135 debugger tests pass (test/debugger/*.test.js): Debugger.test.js, DebuggerUI.test.js, debugger-playback.test.js, debugger-breakpoints.test.js — 0 failures.
- Full `npm test`: 11 failures, all in test/ui/ due to a pre-existing `ReferenceError: Cannot access 'AppController' before initialization` TDZ in src/ui/app-controller-circuit.js:9 (an unrelated in-progress app-controller refactor already present untracked in the working tree before this task). Baseline on the original code shows 21 failures, confirming these UI failures predate this change and none are caused by the debugger split. No debugger test fails.

No default exports, no barrel files, explicit .js extensions, no circular imports at runtime, all files under 400 lines.
