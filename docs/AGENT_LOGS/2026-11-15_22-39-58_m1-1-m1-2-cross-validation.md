Title: Sprint 4 M1.1 + M1.2 cross-validation tests (SHA-256 vs crypto, Complex vs cmath)

Summary:
Implemented M1.1 and M1.2 from docs/Plans/S4.md.

M1.1 — SHA-256 cross-validation vs Node.js built-in `crypto`:
- New test/cross-validation/sha256-vs-crypto.test.js comparing Cache.sha256Hex(input) byte-for-byte against crypto.createHash('sha256').update(input).digest('hex') across: empty string, single ASCII char, deterministic random strings (lengths 0–2048 via seeded mulberry32 PRNG), Latin-1 supplement / non-BMP / surrogate-pair inputs, real circuit JSON from Serializer.toJson, and the cache-key format `${canonicalJson}|${schemaVersion}|${promptVersion}` (including determinism and version sensitivity).
- Fixed a padding-length bug in src/ai/Cache.js sha256Hex: the paddedLenBits formula added an extra 512-bit block for messages whose bit length falls in [384, 447] and for larger multi-block messages, causing digest mismatches vs Node crypto. Replaced with Math.ceil((bitLength + 1 + 64) / 512) * 512.

M1.2 — Complex arithmetic cross-validation vs Python stdlib cmath:
- New test/cross-validation/cmath_ref.py reference script (spawned as a child process, skipped gracefully when python3 unavailable).
- New test/cross-validation/complex-vs-analytical.test.js comparing Complex add/sub/multiply/divide/conjugate/magnitude/phase/fromPolar against hand-computed analytical values (always run) and against cmath via the reference script (120 randomized cases across all operations, tolerance 1e-12 per component). Covers divide-by-zero RangeError and TypeError edge cases.
